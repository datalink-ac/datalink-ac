# SEO 思考：理念站的 SEO 跟产品站不是一回事

> 台账（现在什么状态）在 issue #2：
> https://github.com/datalink-ac/datalink-ac/issues/2
>
> 这里记的是**为什么这么定**，以及**哪些还没定**。

## 一个前提：理念站的 SEO 是两件事

产品站排的是「我要买 X」的词，进来的是买家。
理念站排的是「这个东西叫什么」的词，进来的是两类人：

1. 正好撞上这个问题、但还没有词汇去描述它的人（搜索来的）
2. 已经听说过、想看看它到底是什么的人（**链接来的**，不是搜索来的）

第二类人根本不会搜「datalink」——他们搜的是自己正在解决的那个问题，
而你是被别人引用过去的。

所以结论是：

> **技术 SEO 便宜、一次性；真正决定生死的是「可被引用」。**

技术底子该做的一定做（一个下午的事），但别把它当成 SEO 的主体。
主体是：有没有一篇东西好到别人必须引用它。

## 审计出来的那几处，为什么都算「硬伤」

理念站的全部资产就是那十几个页面。metadata 错了，
站点就恰好对**最可能引用它的那批读者**隐身了。

- **博客索引页和隐私页没有 `<h1>`** —— 一个连自己主题是啥都说不清的页面，
  搜索引擎也不确定该把它归到哪。
- **文章标题没有品牌** —— 搜索结果里只有「Data in the link」，没有「datalink.ac」。
  理念站的名字就是它的定位，标题里不能没有它。
- **首页 description 172 字** —— 后半截被截掉，而被截掉的那半截正好是
  「人拿到什么、agent 拿到什么」这句最值钱的话。
- **配图没尺寸** —— 布局跳动。理念站读者多半是在手机上扫的，抖一下就走了。
- **404 没 noindex** —— 站点会把自己的 404 收进索引。
- **sitemap 的 `lastmod` 用构建时钟** —— 每次构建全站都变一遍，
  等于训练爬虫忽略这个字段。改成源文件真实修改日。

## 几个刻意的选择

**robots 挡掉 `/d.json` 与 `/deck`，但放行 `/d`。**
前两个是工具面，不是内容；`/d` 是渲染出来的图，可以合理地进图片搜索，
而且那些链接本来就是这个站点要展示的东西。

**不写 meta keywords。** Google 早不看了，写它是 cargo cult。

**不做站内统计。** 见 [[20261112-datalink-privacy]]——这个站没有 cookie、没有统计脚本、
没有追踪。代价是真实的：**我们看不到自己的流量**。
所以 Search Console 不只是「顺便加上」，它是这份 SEO 工作里**唯一的真相来源**。
这条要记住，别以后稀里糊涂加个 GA 上去。

**不用网络字体。** 性能是排名因素，而字体请求是一个我们并不需要的第三方依赖。

**资源链接带 build id。** 部署之后访问者继续吃上一次的 CSS 是个静默回归——
页面上线了，样式没上。这个坑我自己踩了一次才补上。

**`lastmod` 用文件时间，不用时钟。** 用时钟的 `lastmod` 是谎话，
而且会让爬虫学会忽略这个字段。

**sitemap 的 `hreflang` 两个方向都列。** 我们一开始只列了「另一种语言」，
缺了自身那一条——那是 bug，不是风格。爬虫期望每个条目都带上完整的语言集合。

## 还没定的

- **双语到底怎么定位？** `/en` 与 `/zh` 现在是平等索引的两份。
  如果是「一份给所有人、一份给中文读者的便利版」，那 canonical 应该只指一边；
  如果真的是两个读者群，那就该平权。**这条影响面最大，还没想清楚。**
- **`/d` 生成的 URL 到底该不该进索引？** 现在是可爬的。
  爬虫顺着页面上的链接爬，会爬到一大堆生成的 SVG——那是索引噪音。
  可能要给它加 `noindex` 或 canonical 指回概念页。
- **博客 slug 带日期**（`/blog/261112-…`）：现在没问题，也和 x-cmd.com 一致；
  但链接贴出去看着有点怪。博客长了再重新考虑。
- **每页各自的 OG 图**：现在是全站共用一张。

## 不做的事

- 链接农场、外链买卖
- 关键词堆砌
- 为了数量而写文章（AI 灌水对理念站是负资产——它本来卖的就是「讲透」）
- 为了排名把标题改成搜索引擎喜欢的样子（标题是给人看的）
