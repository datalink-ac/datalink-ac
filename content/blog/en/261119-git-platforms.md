When a datalink lands in an issue, the picture is not drawn by the reader's
browser — the platform's servers fetch it first, store it, and hand it over.
So whether a link works is not up to the renderer. It is up to the platform.

We pasted the same set of links into issues on six platforms: GitHub, GitLab,
Gitee, GitCode, Codeberg (Forgejo) and Bitbucket (Atlassian). Pie, radar,
diagrams, calendars, molecules, maps — more than a dozen kinds — plus a ladder
of links built to test length: 4000, 4096, 5000 characters, one rung at a time.

This is not a datalink problem — it is a gate every image link passes through.
The platform's fetch server caps the URL length. The middleman that fetches
pictures for every reader does not want to carry addresses that long; that is
how GitHub's [image
proxy](https://github.blog/news-insights/product-news/proxying-user-images/)
works.

## Run through this before you paste

- **Length**: on GitHub and GitCode, keep image URLs under 4000 characters.
  Charts, diagrams and calendars are far short of it; what runs over is maps
  with every region in, or diagrams with dozens of nodes. If you must paste
  one, use a short link first: POST the spec to the renderer and take the
  short URL it gives back.
- **Caching**: platforms cache by URL. Change the link and you get a new
  picture; leave it alone and the platform may serve its cached render for a
  while, expiring on its own. Pin `v=1` for a picture that must never change;
  a picture that follows the data should not be pinned in the first place.
- **Colour scheme**: `scheme=auto` follows the reader's system — but what the
  platform fetches is the scheme at the moment of fetching. To give every
  reader the same colours, write `scheme=light` or `scheme=dark`.
- **SVG**: all six tested platforms pass SVG through. But mail clients and
  some chat tools block external images — glance before you paste there.
- **Privacy**: proxying means a platform server visits the renderer once, so
  the platform can see what is in the link. The link was public anyway — this
  is not a leak, just do not mistake "the platform fetched it too" for a
  surprise.
