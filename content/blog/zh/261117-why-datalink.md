date: 2026-11-17

这个名字差点是随手起的，后来不得不为它辩一辩。候选是 **infolink**、**linkdata**、
**dataurl**。下面是它们各自输在哪儿。

## 是 data，不是 info

`info` 更含糊，而含糊正是问题所在。

每条链接都带着信息 —— 一个页面、一篇文章、一个登录页。datalink 带的是
**真的数据**：数字本身，在 URL 里，是机器不用问任何人就能读的形式。那比
「信息」窄一点，也比它硬一点。

要紧的不是「链接里有信息」，而是**数据就放在 URL 上，而服务是
stateless 的** —— 不要账号，不要云上的一份拷贝，不要任何必须一直活着的东西
才能让链接继续成立。

## 是 link，不是 url

`url` 是个术语。它放在 HTTP 头里是对的，放在一个作者要往 README 里粘贴的
页面上是错的。

`link` 是大家本来就有的词。它说清了这东西在日常语言里干什么：你把它
发出去，别人点开，看见东西。

## 是链接的一种，不是数据的一种

`linkdata` 的中心词错了。读起来是*挂在链接上的数据* —— 链接是修饰语，数据
才是主体。但这件事的主体是链接本身：**链接的一种**，恰好带着数据。

`dataurl` 也是。它读起来像*下载数据的地方* —— 一个数据仓库，一个接口，
在别处。而 datalink 的全部要害正是：数据不在别处，就在你正在发的这条
链接里。

## data in the link

所以这个名字按事情本身的样子说：

> **data** —— 真的数据，不是数据的图片，也不是数据的说明
> **link** —— 你发、别人点、随手粘的那个东西，用的是大家都有的词

**datalink** 就是一条带着数据的链接。

名字不是论据 —— 论据是[规范](https://datalink.ac/zh/spec)。但名字是一个
概念的第一句话，这句话是真的。
