这个名字想了挺久。infolink、linkdata、dataurl 都想过，最后选了 datalink。

（1）先说 info

链接里带信息，这事儿不新鲜，每条链接都带。我们说的是更具体的一件事：数字本身
就放在 URL 上，服务那边什么都不存。

这样链接才能是「无状态」的：明天再看，它还是一个意思；就算背后的服务挂了，
它还是一个意思。

到这一步，用 data 比用 info 准。

（2）再说 url

会往 README 里贴这种链接的人，想的不是 URL，是链接。URL 是术语，link 是他们
本来就有的词。

dataurl 还有个问题：听着像「下载数据的地方」，一个数据仓库、一个接口，在别处。
可数据不在别处啊，它就在你正要发出去的那条链接里。

（3）linkdata

linkdata 的中心词反了。它读起来像是「挂在链接上的数据」，数据是主，链接是宾。

我们要的正好反过来：是链接的一种，恰好带上了数据。

（另外，这个名字已经有人在用了，我们知道得晚。）

（4）datalink

data in the link。

事情是这样，名字也就是这样。
