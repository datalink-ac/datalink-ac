链接是有长度的，而且处处受限。GitHub 的图片代抓对超过约 4096 字符的
地址直接拒绝——上一篇实测过，一张 120 步的流程图 URL 约 4.9k 字符，
就顶在这堵墙上（[六个平台的实测](/zh/blog/261119-git-platforms)）。

墙的本质：替所有读者抓图的中间人，不想替太长的地址背锅。这个动机
不会消失，所以问题不是「墙什么时候拆」，而是**数据比墙长的时候，
安置在哪**。

datalink 的答案有三条，按推荐的顺序。

## 出路一：短链（今天可用）

把规格 POST 给渲染器，换一条短 URL 回来。实测：

```
$ curl -X POST https://www.x-cmd.com/draw?type=pie \
    -d '{"title":"Share me","data":[{"label":"A","value":3},{"label":"B","value":2}]}'

{"hash":"ba9f3be03d00e76a","url":"https://www.x-cmd.com/draw/c/ba9f3be03d00e76a","template":"pie"}
```

这条短链不是随机 id，是**数据的指纹**：实现把规格做规范化（对象键排序、
数组不动——数组顺序就是数据的顺序），再哈希。所以相同的数据永远
得到相同的短链，实测键的顺序打乱也不影响；而数据真变了，指纹自然
变。这让短链可以缓存、可以分享、可以被引用——它和长链接遵守同一套
承诺，只是数据的住处从 URL 搬到了渲染器的存储里。

住处搬了，账也要认：短链不再是自包含的，链接本身读不出数据了。
所以规范要求渲染器为这类链接提供机器可读的规格视图——JSON 输出或
`/draw/explain` 解析端点（形态在规范 §9 待决，推动在
[x-cmd/draw#43](https://github.com/x-cmd/draw/issues/43)）。

短链还有一个天生的短板：它本身不带信息。读者和 agent 拿到
`/draw/c/ba9f3be03d00e76a`，看不出这张图在讲什么。补法是把上下文
挂在链接上——`_ctx=这张图是 Q3 的代码构成，A 是 TypeScript`。
今天的渲染器会忽略这个参数（实测照常出图），但它跟着链接走，读链接的
agent 读得到；explore 里把它显示出来，是下一步的事。

## 出路二：链接压缩（设计好了，还没落地）

把规格压缩后塞进参数，链接还是自己带着数据——自包含不破。
代价和 base64 一样：**压缩的数据 agent 在上下文里读不懂**，要一次
解码才用得了，「拿到链接就有数据」这条承诺实际上退了半步。

所以它只该出现在无可奈何的场景：你既不想用短链，又刚好顶到平台的
长度墙。这是设计里的兜底位，不是首选（变体取舍记在
[issue #8](https://github.com/datalink-ac/datalink-ac/issues/8)）。

## 出路三：模板 + 关键数据（设计里）

另一条路把「样式」和「数据」拆开：模板（一份样式，甚至一张底图
svg）上传到服务成为一条 template 链接，参数里只放关键数据。
链接短了，样式还能复用——一批同款的图共享一个模板，改样式只动
模板。规格层面的设计在 issue #8，落地排期未定。

## 一个态度：短链不设过期

托管数据有成本，常见做法是短链设 TTL，过期的删。datalink 不打算
这么做：**用户的数据是宝贵的，平台不应该乱删**——一条链接贴进
issue，三年后被翻出来，图还得在。成本用另一堵墙挡：价格。滥用
的人付代价，认真用的人链接永在。删数据和收费之间，选收费。

## 怎么选

| 情况 | 出路 |
| --- | --- |
| 链接在 3.8k 以内 | 什么都不用做，长链接是最自包含的形态 |
| 顶到平台长度墙，数据可以离链 | 短链，上下文挂 `_ctx=` |
| 不想数据离链，又必须过墙 | 压缩（落地后），接受 agent 要解码 |
| 一批同款图、要统一换肤 | template + 关键数据（落地后） |

## 收尾

链接太长，表面是地址栏的问题，本质是**数据住哪**的问题：住进
URL，自包含、谁都能读，但有墙；住进渲染器，地址短了、永在，但要
为「读数据」补一个视图、为「滥用」立一堵价格墙。三条出路是同一条
守恒定律的三种解法——数据不会消失，只会搬家；搬家的代价，就是
链接形态的设计空间。
