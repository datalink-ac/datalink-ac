THE PROBLEM

A picture is a lovely way to lose a number.

You ask your AI for a chart. You get a picture — which is exactly what you wanted to put in your draft. But behind the picture there was a table, and the table is gone. From here on, every number in your draft is something somebody read off an image.

the picture

You cannot check it

The bar might say 4.18. Your draft will say 4.2, or 4.3, or 42%. Nobody can tell which, because the numbers are not in the picture.

the model

It reads pixels, not data

An AI handed an image recovers the values by looking at it. It is good at that. It is also guessing, and it does not know which parts it guessed.

the fix

You ask again

“Are those numbers right?” — another round trip, another guess, another chance to be confidently wrong in a slightly different way.

None of this is the model’s fault. We built pictures for eyes, and then handed the pictures to something that has to do arithmetic on them.
THE IDEA

Put the data in the link.

One web address, carrying the data itself. Open it and you get the picture. Fetch it and you get the numbers, exactly as they were measured. There is no second version of the truth to keep in sync — there is only the link.

TWO READERS

One link, and each one gets what they need.

The link is the artefact, and it serves both — with no translation step in between, so nothing is lost in between.

the human · gets the picture

  • Vivid. A picture carries the shape of the data at a glance — the trend, the outlier, the proportion.
  • Immediately legible. Nothing to learn, no interface to master. The eye has it in a second.
  • One consistent design. The same visual language everywhere, so the reader's attention goes to what the data means — not to how it is styled.
  • Least mental effort. No setup, no login, no clicking through filters to reach the one view that matters.
  • Information, maximally compressed. One picture says what a hundred-row table says, in a fraction of the space.

the agent · gets the data

  • Exact, no hallucination. The numbers themselves, not a reading of them. No rounding, no OCR, no estimating from pixels.
  • Cheaper. Text costs about four characters a token; re-reading the same chart as an image costs hundreds of vision tokens, every single time.
  • Faster reasoning. One fetch returns the picture and the spec together — no second round trip, and the context window stays free for the part that matters.
A WEEK OF WRITING

What it is like to actually use one.

You are writing the quarterly post. You have the numbers. The rest is four steps, and none of them involve asking anyone for anything.

1

You have the numbers

A sheet, a query, a dashboard you already log into. Nothing changes here — this is the part you already do.

2

You make a link

Paste the data into the address. A chart appears — and now the chart and the data are the same thing, travelling together.

3

You paste it in your draft

Your reader sees a chart instead of a wall of numbers. Your AI, working on the same draft, can fetch the same link and read the exact values behind it.

4

Someone asks “and last quarter?”

You change one thing in the link and paste it again. No dashboard, no export, no waiting for anyone to redraw anything.

And the part that matters most. Because the link is in the draft, the numbers travel with the picture. Six months later, when someone asks where 4.18 came from, the answer is a link — and it still opens.
WHAT ELSE

It is not only charts.

Nothing about “the data lives in the address” is specific to pie charts. The same flat parameters draw a structure, lay out a table, fill a calendar, or make a deck. The drawing changes; the link does not.

Every tab is one link. The charts and diagrams come from x-cmd/draw, the deck from x-cmd/ppt, the table from this site.

WHERE IT STARTS

The first place it earns its keep is GitHub.

Not a dashboard. Not a BI tool. The places where text already lives and pictures do not: an issue, a pull request, a release note. Written in words, read by people, and — increasingly — by bots. A link fits all three. A screenshot fits none.

release · v0.3.0bar

A release note wants to say “+2,400 lines, mostly TypeScript”. That sentence is a table. As a link it is also a chart — and it stays greppable, diffable and readable by whatever triages the repo.

issue · “what does this do?”use case

Three paragraphs explaining a feature age faster than one diagram. And because it is a link, the next person can move a box instead of asking for a redraw.

pull request · “what changed?”mind map

The one picture a reviewer actually asks for. As a link it is reviewable: change a parameter in the pull request and the picture changes with it. A screenshot cannot be reviewed.

the link
Why GitHub comes first. Everything there is already text: a diff, a comment, a release note. A datalink drops into that world without asking anybody to change a habit — and a bot reading the issue gets the numbers, not a picture of them.
TRY IT

Your AI already knows how to read a link.

Teach it to make datalinks with one small skill, and then ask for a chart the way you would ask for anything else. No key, no account, no dashboard — the agent composes a link and the chart appears.

a prompt worth pasting
Make me a pie chart of our newsletter subscribers by month since January.
Give me the exact numbers — read them from the link, not from the picture,
because I want the values, not your reading of them. Then send me the link
so I can change the range myself.

That prompt is the whole idea in three sentences: ask for a chart, forbid the lossy step, and ask for the link back — because the link is an instrument, not a picture of one.
