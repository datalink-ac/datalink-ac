THE PROBLEM

A picture is a lovely way to lose a number.

Your AI writes the piece. Where it needs a chart, it makes one — and a chart it made is a picture with no numbers behind it. So every number in the finished piece is a value it read off pixels.

the picture

The numbers are not in it

The bar might say 4.18. The piece will say 4.2, or 4.3, or 42%. Nobody can tell which, because the numbers are not in the picture.

the model

It reads pixels, not data

Given an image, an AI recovers the values by looking at it. It is good at that. It is also guessing — and it does not know which parts.

the reader

They trust it

The piece goes out with a number in it that nobody checked. A reader who trusts the writing has no way to tell.

THE IDEA

Put the data in the link.

One address, carrying the data itself. Open it and you get the picture; fetch it and you get the numbers, exactly as measured. There is no second version of the truth to keep in sync — there is only the link.

TWO READERS

One link, and each one gets what they need.

The link is the artefact, and it serves both — with no translation step in between, so nothing is lost in between.

the human · gets the picture

  • Vivid. A picture carries the shape of the data at a glance — the trend, the outlier, the proportion.
  • Immediately legible. Nothing to learn, no interface to master. The eye has it in a second.
  • One consistent design. The same visual language everywhere, so the reader's attention goes to what the data means — not to how it is styled.
  • Least mental effort. No setup, no login, no clicking through filters to reach the one view that matters.
  • Information, maximally compressed. One picture says what a hundred-row table says, in a fraction of the space.

the agent · gets the data

  • Exact, no hallucination. The numbers themselves, not a reading of them. No rounding, no OCR, no estimating from pixels.
  • Cheaper. Text costs about four characters a token; re-reading the same chart as an image costs hundreds of vision tokens, every single time.
  • Faster reasoning. One fetch returns the picture and the spec together — no second round trip, and the context window stays free for the part that matters.
THE FLOW

One prompt in. A report whose charts are links.

The agent writes the piece — a README, an issue, a pull request, a post — and where it needs a chart it composes a link instead of pasting an image. The report looks the same as ever; what changed is that every chart still holds its numbers.

what the reader gets

A report that looks finished

Charts from one renderer, the same every time — not whatever the agent improvised that day.

what stays behind

Links that still hold the data

Every picture is a link with the numbers inside it. Nothing was flattened on the way.

what it means later

Memory that can be re-read

Six months on, an agent with memory reads the link and finds the intent and the numbers — not a picture of them.

That last one is the real prize. A screenshot in a chat log is a dead end: the thinking behind it is gone, and so are the numbers. A link keeps both — which is what makes a report something an agent can work from again, instead of something it has to take on faith.
WHAT ELSE

It is not only charts.

The same flat parameters draw a structure, lay out a table, fill a calendar or make a deck. The drawing changes; the link does not.

Every tab is one link. The charts and diagrams come from x-cmd/draw, the deck from x-cmd/ppt, the table from this site.

WHERE IT STARTS

The first place it earns its keep is GitHub.

Not a dashboard, not a BI tool: the places where text already lives and pictures do not — an issue, a pull request, a release note. Written in words, read by people, and by bots. A link fits all three; a screenshot fits none.
