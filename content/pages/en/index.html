THE PROBLEM

The picture is not the data.

Your AI writes the piece with the data in hand. What it leaves behind is a picture — and the data went into the image and did not come back out of it. Next month, whoever reads the piece has the picture and nothing else.

the picture

It shows; it does not hold

A chart can show you the shape of a hundred numbers. It cannot hand you the hundred numbers.

the model

It reads pixels

Given the picture, a model reconstructs the values by looking. It is good at that — and it is still a reading, and it cannot tell which parts it read and which it filled in.

the artefact

There is nothing to check against

The piece ships; the context that made it does not. Whoever reads it next — a person, an agent, you next year — has the picture, and no data to compare it to.

THE IDEA

Put the data in the link.

One address, carrying the data itself. Open it and you get the picture; read it and you get the numbers — they are right there in the address, exactly as measured. There is no second version of the truth to keep in sync, because there is only the link.

TWO READERS

One link, and each one gets what they need.

The link is the artefact, and it serves both — no translation step, so nothing is lost.

the human · gets the picture

  • Vivid. A picture carries the shape of the data at a glance — the trend, the outlier, the proportion.
  • Immediately legible. Nothing to learn, no interface to master. The eye has it in a second.
  • One consistent design. The same visual language everywhere, so the reader's attention goes to what the data means — not to how it is styled.
  • Least mental effort. No setup, no login, no clicking through filters to reach the one view that matters.
  • Information, maximally compressed. One picture says what a long table says, in a fraction of the space.

the agent · gets the data

  • Exact, no hallucination. The numbers themselves, not a reading of them. No rounding, no OCR, no estimating from pixels.
  • Cheaper. Text costs about four characters a token; re-reading the same chart as an image costs hundreds of vision tokens, every single time.
  • Faster reasoning. The link is already in the text, and the numbers are already in the link. No image to fetch, nothing to look at, no second call — and none of the context window spent on pixels.
THE FLOW

One prompt in. A report whose charts are links.

The agent writes the piece — a README, an issue, a pull request, a post — and where it needs a chart it composes a link instead of pasting an image. The report looks the same as ever; what changed is that every chart still holds its numbers.

what stays behind

what it means later

Memory that can be re-read

Six months on, an agent with memory reads the link and finds the intent and the numbers — not a picture of them.

That last one is the real prize. A chart in a chat log is a dead end: the numbers behind it are gone, and whoever reads it later has to reconstruct them from pixels. A link keeps the numbers — and its parameters say what was being measured and how it was framed. That is what makes a report something an agent can work from again, instead of something it has to take on faith.
TWO CASES

Two costs you stop paying.

A picture is a file. Files have to be re-made, re-uploaded and committed again — and a repository full of them gets heavier every time a number changes. A link is text. Text just changes.

case one

Your README has numbers in it

Today. The number changes, so the chart is re-rendered, re-uploaded and committed as a binary. The repository grows, and the diff says “image changed” — not what changed.

With a datalink. The agent changes one number in the URL and commits. The diff shows the number, the picture follows it, and a year later the history still says what you meant.

case two

You ship the same docs in five languages

Today. Five languages, five chart files, five renders, five commits — and every change to the data means doing it five times.

With a datalink. The language is a parameter. Five charts, five URLs, one line of text each — generated from the same source by the same agent.

Same numbers, six languages, six links — the language lives in the parameters (title and labels alike). No six files, no six renders, nothing to keep in sync.

WHAT ELSE

It is not only charts.

The same flat parameters draw a structure, lay out a table, fill a calendar or make a deck. The drawing changes; the link does not.

Every tab is one link. datalink.ac/d is the same service as x-cmd.com/draw — the address is the only difference. Click any picture to open it in the explorer and change it by hand.

WHERE IT FITS

GitHub is where it fits best.

Issues, pull requests, release notes — text, read by people and by bots. A datalink drops into that world and keeps the numbers with it: reviewable, changeable, and readable by a bot that has to work from the picture.
