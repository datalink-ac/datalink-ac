问题

图片是个很优雅的丢数字的方式。

稿子是 AI 写的。它需要一张图的时候，就做一张图—— 而它做出来的图，背后没有数字。 所以成稿里的每一个数字，都是从像素上读出来的。

那张图

数字不在里面

那根柱子可能是 4.18。稿子里会写 4.2，或者 4.3，或者 42%。没人能分辨，因为数字根本不在图里。

那个模型

它读的是像素，不是数据

拿到图片的 AI，是靠「看」把数值还原出来的。它很擅长这个。它同时也在猜，而且它不知道自己哪些地方在猜。

读者

他们信了

稿子带着一个没人核对过的数字发出去。信任这份文字的读者，没有办法分辨。

想法

把数据放进链接里。

一条网页地址，里面装着数据本身。打开它，你看到图； 取它，你拿到数字，和当初测量的一模一样。 不存在第二个需要同步的「真相版本」—— 只有这条链接。

一

链接

一条普通的网页地址，由你的 agent 拼出来。它装着数据——不是某个页面的指针，不是截图，就是数据。

二

图

读者看到的。图表、表格、结构图——每次都由那份数据画出来。

三

数据视图

agent 取链接时拿到的。同样的数字，变成可以直接引用的文本。

两个读者

一条链接，各自拿到自己需要的。

链接就是那个产物，它同时服务两边——中间没有翻译这一步，所以也没有翻译的损耗。

人 · 看到图

  • 生动。 一张图一眼就带着数据的形状——趋势、离群、占比。
  • 一看就懂。 不用学，没有界面要掌握。眼睛一秒就拿到。
  • 设计统一。 到处是同一套视觉语言，读者的注意力花在数据表达的意图上，而不是样式上。
  • 心智负担最低。 不用配置、不用登录、不用点半天筛选器才看到真正要的那一屏。
  • 信息被最大程度压缩。 一张图说清一张百行表说的东西，占的空间只有零头。

agent · 拿到数据

  • 准确，无幻觉。 数字本身，不是对数字的读法。不四舍五入，不 OCR，不从像素上估。
  • 省钱。 文本大约四个字符一个 token；同样的图反复读成图片，每次都要几百个视觉 token。
  • 加快推理速度。 取一次，图和规格一起回来——不用第二次往返，上下文窗口留给更值得的事。
怎么跑

一段 prompt 进去，一份图表全是链接的报告出来。

稿子是 agent 写的——README、issue、pull request、或者一条帖子—— 它需要图的时候，就拼一条链接，而不是贴一张图片。 报告看起来和平常一样；变的是每一张图都还揣着自己的数字。

复制这段
写一篇 Q3 复盘——每月的新增、流失和营收，各配一张图。
图用数据链接，链接留着，以后我们能从里面直接取数字。

读者拿到什么

一份看起来做完了的报告

图都出自同一个渲染器，每次都长一个样——不是 agent 当天随手拼出来的样子。

背后留下什么

还装着数据的链接

每张图都是一条链接，数字在里面。一路上什么也没被压平。

往后意味着什么

能被重新读回来的记忆

半年之后，有记忆的 agent 读那条链接，能读出当时的意图和数字，而不只是它们的照片。

最后这一条才是真正的奖品。 聊天记录里的一张截图是条死路： 背后的判断没了，数字也没了。链接两样都留着—— 这才是报告能被 agent 再次拿去用的原因，而不是只能被相信。
还可以是什么

不只是图表。

同一套扁平参数能画出结构、排出表格、填满日历、做成幻灯片。 换的是画法，不变的是链接。

每个标签页都是一条链接。图表和结构图来自 x-cmd/draw， 幻灯片来自 x-cmd/ppt， 表格来自本站。

从哪开始

它最先证明自己的地方，是 GitHub。

不是仪表盘，不是 BI 工具。是那些「文字本来就在、图片本来就不在」的地方： issue、pull request、release note。 用字写的，给人读，也越来越多被 bot 读。 链接三样都合适；截图一样都不合适。

release · v0.3.0bar

「新增 2400 行，主要是 TypeScript」这句话本来就是一张表。做成链接，它同时是一张图——而且依然可 grep、可 diff，也能被整理仓库的 bot 读懂。

这条链接
issue · 「这东西是干嘛的？」用例图

用三段话解释一个功能比一张图老得快；因为是链接，下一个人能直接挪一个框，而不是开口要求重画。

这条链接
pull request · 「改了什么？」思维导图

这是 reviewer 真正会要的那张图。作为链接它是可以审的：在 PR 里改一个参数，图跟着变。截图没法被审。

这条链接
为什么 GitHub 排在第一。 那里的一切本来都是文本：一个 diff、一条评论、一份 release note。 数据链接不用任何人改习惯就能落进去。而且读 issue 的 bot 拿到的是数字，不是数字的照片。
试一试

你的 AI 早就会读链接了。

用一个小小的 skill 教会它把数据链接做对。不用密钥、不用账号、不用仪表盘—— agent 把链接拼出来，图就出来了。

装上 skill
npx clawhub@latest install edwinjhlee/x-cmd-draw
或者直接取一条链接
curl 'https://datalink.ac/d?type=pie&labels=TS,Py,Go&values=4821,2312,980'

skill 是可选的——读完这一页的 agent 本来就会拼链接。 上面「怎么跑」那段的 prompt 直接就能用，skill 只是把形状教给它。
