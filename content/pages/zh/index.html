问题

图不是数据。

稿子是 AI 写的，写的时候数据在它手里。可它留下的是一张图—— 而数据进了那张图，就没再出来。 下个月再读这篇东西的人，手里只有那张图。

那张图

它显示，不保存

一张图能让你看出一百个数字的形状，但它没法把那一百个数字交给你。

那个模型

它读的是像素

拿到图片，模型靠「看」把数值还原出来。它很擅长这个——但它终究是在读，而且它分不清哪些是读出来的、哪些是补上去的。

那份产物

没有东西可核对

稿子发出去了，写它的上下文没有。下一个人来读——一个人、一个 agent、或者一年后的你——手里只有那张图，没有数据可以对照。

想法

把数据放进链接里。

一条网页地址，里面装着数据本身。打开它，你看到图； 读它，你拿到数字——它们就在地址里，和当初测量的一模一样。 不存在第二个需要同步的「真相版本」，因为只有这条链接。

一

链接

一条普通的网页地址。它装着数据——不是某个页面的指针，不是截图，就是数据。

二

图

读者看到的。图表、表格、结构图——每次都由那份数据画出来。

三

数字

agent 读到的东西。已经在地址里了——精确、可引用，不用「看」。

读者 · 图

加载中…

读者要的东西，一眼就够。

同一个链接

你的 AI · 链接

加载中…

你的 agent 改一个参数，就得到另一张图——不用重画，不用导出，不用求谁。 试试：改上面那个数字，回车。

两个读者

一条链接，各自拿到自己需要的。

链接就是那个产物，它同时服务两边——没有翻译这一步，所以也没有损耗。

人 · 看到图

  • 生动。 一张图一眼就带着数据的形状——趋势、离群、占比。
  • 一看就懂。 不用学，没有界面要掌握。眼睛一秒就拿到。
  • 设计统一。 到处是同一套视觉语言，读者的注意力花在数据表达的意图上，而不是样式上。
  • 心智负担最低。 不用配置、不用登录、不用点半天筛选器才看到真正要的那一屏。
  • 信息被最大程度压缩。 一张图说清一张长表说的东西，占的空间只有零头。

agent · 拿到数据

  • 准确，无幻觉。 数字本身，不是对数字的读法。不四舍五入，不 OCR，不从像素上估。
  • 省钱。 文本大约四个字符一个 token；同样的图反复读成图片，每次都要几百个视觉 token。
  • 加快推理速度。 链接本来就在正文里，数字本来就在链接里。不用取图、不用再看一遍、不用第二次调用，上下文窗口一点也没花在像素上。
怎么跑

一段 prompt 进去，一份图表全是链接的报告出来。

稿子是 agent 写的——README、issue、pull request、或者一条帖子—— 它需要图的时候，就拼一条链接，而不是贴一张图片。 报告看起来和平常一样；变的是每一张图都还揣着自己的数字。

复制这段
写一篇 Q3 复盘——每月的新增、流失和营收，各配一张图。
图用数据链接，链接留着，以后我们能从里面直接取数字。

读者拿到什么

一份看起来做完了的报告

图都出自同一个渲染器，每次都长一个样——不是 agent 当天随手拼出来的样子。

背后留下什么

还装着数据的链接

每张图都是一条链接，数字在里面。一路上什么也没被压平。

往后意味着什么

能被重新读回来的记忆

半年之后，有记忆的 agent 读那条链接，能读出当时的意图和数字，而不只是它们的照片。

最后这一条才是真正的奖品。 聊天记录里的一张图是条死路： 背后的数字没了，后来的人只能从像素上把它重建回来。 链接把数字留住——而且参数本身就说明了当时在量什么、怎么量的。 这才是报告能被 agent 再次拿去用的原因，而不是只能被相信。
两个场景

两种不用再付的成本。

图是文件。文件要重做、重传、再提交一次——仓库里堆着这种二进制文件， 每改一次数字就胖一圈。链接是文本。文本只要改。

场景一

你的 README 里有数据

今天。 数字变了，图就得重渲染、重上传、再当二进制提交一次。仓库在胖，而 diff 只说「图片变了」，不说变了什么。

用数据链接。 agent 改链接里的一个数字，提交。diff 里就是那个数字，图跟着变；一年后提交历史还说得清你当时的意思。

场景二

同一份文档要出好几种语言

今天。 五种语言，五张图文件，五次渲染，五次提交——而数据每改一次，就要做五遍。

用数据链接。 语言只是一个参数。五张图，五条 URL，每条一行文字——由同一个 agent 从同一份来源生成。

同样的数字，六种语言，六条链接——语言就住在参数里（标题和标签都是）。 没有六个文件，没有六次渲染，也没有东西要同步。

还可以是什么

不只是图表。

同一套扁平参数能画出结构、排出表格、填满日历、做成幻灯片。 换的是画法，不变的是链接。

每个标签页都是一条链接。datalink.ac/d 和 x-cmd.com/draw 是同一个服务，区别只在地址。点任何一张图，都能在 explorer 里打开，手动改。

从哪开始

它最先证明自己的地方，是 GitHub。

不是仪表盘，不是 BI 工具——是那些「文字本来就在、图片本来就不在」的地方： issue、pull request、release note。 用字写的，给人读，也越来越多被 bot 读。 链接三样都合适；截图一样都不合适。

这条链接
为什么 GitHub 排在第一。 那里的一切本来都是文本：一个 diff、一条评论、一份 release note。 数据链接不用任何人改习惯就能落进去。而且读 issue 的 bot 拿到的是数字，不是数字的照片。
试一试

你的 AI 早就会读链接了。

用一个小小的 skill 教会它把数据链接做对。不用密钥、不用账号、不用仪表盘—— agent 把链接拼出来，图就出来了。

装上 skill
npx clawhub@latest install edwinjhlee/x-cmd-draw
或者直接取一条链接
curl 'https://datalink.ac/d?type=pie&labels=TS,Py,Go&values=4821,2312,980'

skill 是可选的——读完这一页的 agent 本来就会拼链接。 上面「怎么跑」那段的 prompt 直接就能用，skill 只是把形状教给它。
